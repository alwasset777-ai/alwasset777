# w777-brief — من الطلب للإنجاز بلا أخطاء

## 1) الملخص المهني (اكتبو للمستعمل فـ 4–6 سطور بالدارجة، ومن بعد بدا مباشرة)
- **الهدف**: شنو بغا بالضبط (من الكلام + التصاور). إلا كانت صورة: شنو كيبان فيها وفين.
- **النطاق**: الصفحات/الملفات المعنية (`docs/bureau/app.js` …)، وشنو ما غاديش يتبدل.
- **القيود**: فابور 100%، بلا تبديل ديال الحوايج اللي ما طلبهاش، الأمان (ما كاين حتى مفتاح فالكود).
- **الفحص**: كيفاش غادي نتأكدو (اختبار Playwright، صورة شاشة للتيليفون 390px والكمبيوتر 1200px، `node --check`).
- **أفكار**: 2–3 اقتراحات جديدة مفيدة (نفذ اللي صغير وواضح، والباقي اقترحو).

## 2) متى نسول؟
- غير إلا كان اختيار كيبدل النتيجة بزاف وما يتخمنش (مثلاً: شكون يشوف، فين يتحفظ، فابور/دقة). سؤال واحد فيه 2–4 اختيارات، والأحسن هو الأول مع «(Recommended)».
- ما تسولش على حوايج كتقدر تعرفها من الكود.

## 3) التنفيذ
1. اقرا غير الأجزاء اللازمة من الكود (grep قبل read).
2. بدّل بأقل تغيير ممكن، وبنفس أسلوب الكود (تعاليق قصيرة بالدارجة).
3. زيد رقم الـ cache فـ `docs/bureau/sw.js` إلا تبدلات ملفات التطبيق.
4. قاعدة البيانات: زيد SQL فـ `docs/bureau/supabase.sql` وطبقو live (RLS ديما مفعّل).
5. الـ Edge Function: تحقق بـ TypeScript transpile، انشر، وجرب `ping`.

## 4) الفحص قبل النشر (إلزامي)
- `node --check` للملفات المبدلة.
- `tools/tests/crawl.cjs` = 0 أخطاء، + اختبار خاص بالميزة الجديدة، + صورة شاشة كتشوفها بعينيك.

## 5) النشر والتقرير
- commit → push للفرع → PR (عنوان + ملخص) → squash merge → `tools/deploy-pages.sh`.
- التقرير للمستعمل بالدارجة: شنو تدار (نقاط قصيرة)، صور الشاشة، شنو ما تجربش، وشنو باقي (تذكير).
